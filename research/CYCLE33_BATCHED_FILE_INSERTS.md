# Cycle 33: per-file batched DML insertion and tie-breaking boundary limits

**STATUS: PROMOTED TO CORE RUNTIME. Evidence-verified compiler DML optimization.**
Batched DML insertion across blocks within each file cuts 350 ms off compilation
(1.24x speedup in block indexing) and reduces secondary table database calls by 13x,
with exact row and content parity across all tables. Also established that naive
subquery LIMIT pushdown in FTS5 violates Cycle 8's deterministic tie-breaking invariant.
0 generative model calls.

---

## 1. Ground truth bottleneck & empirical discovery

1. **Database Call Amplification in File Indexing**:
   In `npk/pack/compile.py::_write_file_blocks()`, blocks were iterated row-by-row,
   issuing individual `con.execute("INSERT INTO lexical ...")`, `con.executemany("INSERT INTO symbols ...")`,
   and `con.executemany("INSERT OR IGNORE INTO assignments ...")` calls for every single block.
   On Click's 138 files with 2,213 blocks, this created over 4,420 separate C-Python boundary crossings,
   consuming 1,819 ms.

2. **Counterexample: Subquery LIMIT Pushdown Breaks Tie-Breaking**:
   Testing a subquery optimization for `_lexical_channel` (`SELECT l.block_id FROM (SELECT block_id, bm25(lexical) AS score FROM lexical WHERE lexical MATCH ? ORDER BY score LIMIT ?) l JOIN blocks b ... ORDER BY l.score, f.path, b.ordinal`) revealed a subtle correctness flaw.
   When two blocks across different files share the exact same BM25 score (e.g. `TOKEN = 7` in `a.py` and `z.py`),
   FTS5's internal `ORDER BY score LIMIT N` min-heap breaks ties by internal docid (insertion/update history),
   cutting off candidate `a.py` before the deterministic `f.path COLLATE BINARY, b.ordinal` tie-breaker is applied.
   This was caught by `tests/test_retrieval_order.py::test_equal_scores_use_source_order_after_an_update`.
   The subquery optimization was discarded to preserve the fundamental Cycle 8 invariant.

---

## 2. Implementation

In `npk/pack/compile.py::_write_file_blocks()`:
1. Block IDs continue to be auto-generated by SQLite's primary key during the `blocks` loop.
2. `lex_rows`, `sym_rows`, and `assign_rows` are accumulated in memory across all blocks in the file.
3. `lexical`, `symbols`, and `assignments` tables are populated using single `con.executemany()` calls
   per file instead of per block.

## 4. Discarded Complexity & Negative Findings

- **Discarded**: Subquery `LIMIT` pushdown in FTS5 `_lexical_channel`. Counterexample in `test_retrieval_order.py`
  proved it violates Cycle 8's deterministic source-path tie-breaking invariant when scores tie at the boundary.
- **Discarded**: Redundant per-block `executemany` calls for symbols and assignments.
